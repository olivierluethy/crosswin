CrossWin builds and runs your existing WinForms and WPF apps on macOS and Linux, and tells you up front — honestly — whether yours will run. Web and Flutter apps too.

No magic, no promises. CrossWin checks your app against ones it has actually run, labels what's supported, experimental or unsupported, and never fakes a result. Compatibility is a goal it measures, not a guarantee.

How it works

Three steps, no terminal

Open the CrossWin window, point it at a project, and follow the one obvious next action.

Step 1

Open your project

Point CrossWin at a folder — a Windows app, a website, or a Flutter app — or a web address.

Step 2

Check

A plain-language verdict: Ready to run, Worth a try, or Not a match — with the reasons, not jargon.

Step 3

Run

CrossWin builds and launches the real app. See it in the window, click it, and read any errors with the exact file and line.

What runs

Honest support, from real runs

“Supported” means CrossWin has run a comparable app end to end on a real machine — not that yours is guaranteed. Every verdict links back to evidence in the repository.

Get started

Clone, set up, open

macOS (Intel or Apple Silicon) or Linux (x86_64). Setup installs a private .NET SDK and Wine under your home folder — nothing system-wide, no admin.

# 1 — get CrossWin
git clone https://github.com/olivierluethy/crosswin.git && cd crosswin

# 2 — one-time setup (private .NET SDK + Wine, no sudo)
./crosswin setup

# 3 — open the window in your browser
./crosswin gui

Prefer the command line? ./crosswin run <folder> does the same without the window. On Apple Silicon, Rosetta 2 is needed once; on Linux, install Wine 9+ and its fonts. CrossWin prints the exact command if anything's missing.

How CrossWin runs your app. It uses Wine — a compatibility layer that implements the Windows API on macOS and Linux. That is not a Windows virtual machine and not an emulator of Windows; your app's own binaries and the official .NET runtime run on Wine's implementation. Some Windows features behave differently or are missing, which is why CrossWin is explicit about what's supported.

This page can't run apps itself — GitHub Pages hosts static files, so the demo is a labelled simulation. Real execution needs CrossWin installed on your machine.
